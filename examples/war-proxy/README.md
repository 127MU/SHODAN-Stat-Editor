# 空作战列表对照方案

这些方案用于排除特殊战役类型、混合效果与阵营不匹配，不代表本机已实测可游玩。
依据 hd2-network-proxy 提交 `0d0f5e5385b453c7f1a6bcdfb86c8fd1ba19da64`：

- `liberation-lesath.json`：保留用户正在验证的尾宿八 #194，终结族、常规解放、不追加效果。本组合尚未实测。
- `upstream-liberation.json`：#139，仅开放常规战役，保留服务器归属、不追加效果。对应上游 E9 的成功对照；上游显式指定的战役编号由本工具替换为会话内无冲突编号。
- `upstream-exostorm.json`：#93、光能族、常规解放、仅追加一级异界风暴 #1373。对应上游有作战生成记录的事件组合；效果必须仍在本次战争目录中。

先在变种页“导出全部”备份自己的方案。**导入会替换全部星球方案**，不是合并；这样才能排除其他已启用配置。选择一个 JSON 导入，完全退出游戏，开启“应用方案”的变种代理并从 Steam 重启游戏。不要使用“仅采集目录”模式，也不要在原配置中继续叠加这些测试项。

空效果列表表示不追加本工具的效果，服务器原有效果会保留。停止旧会话并重新登录后，上一轮注入的效果不应从客户端缓存继续沿用。

先测尾宿八常规方案；仍为空时，再测上游 #139 对照。若 #139 可游玩而 #194 不行，说明需要进一步定位目标星球/效果组合，而不是继续修改代理连接。若 #139 也为空，需要核对新会话的 `war-proxy/campaign-diagnostics.json`、`health.json` 及实际客户端行为；代理返回 HTTP 200 或显示“已应用”不足以证明任务生成成功。

上游没有提供任意混合效果必然生成任务的算法；`planetEvents` 防守事件补齐后仍报通讯错误，不应作为本问题的补丁。最新新增内容是 type32 战备实验，不是空作战列表修复。
