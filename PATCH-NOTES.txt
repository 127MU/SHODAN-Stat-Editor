SHODAN 数值编辑器 4.1.0-fm3 —— 魔改整合补丁说明（锚点版）
==========================================================

基底：127MU/SHODAN-Stat-Editor main = be765e49（含 PR #10 射击模式、r15 的不可变默认值修复）
文件：
  src/stat_editor.lua   1,367,448 B（LF） → 封包转 CRLF 得 1,390,218 B（本机实测）
  offline/zh_params.lua    40,568 B（LF） → 封包转 CRLF 得 41,219 B
行号均为打完补丁后的位置（LF 文件），用于核对，不作为唯一锚点。

【A】射击模式（fm1）
 A1 11773  新增 MOD.FIRE_MODES（0..8 中文名）与 MOD.FIRE_FUNCTIONS（0/2/3/4/8/11）。
           不用 chunk 级 local：主 chunk 已接近 LuaJIT 200 local 上限。
 A2 13637-13648 武器「开火」分节、rpm 行之后新增 7 行：
      fire_mode / fire_mode_2 / fire_mode_3 → WeaponData +144/+148/+152（u32，allowed 0..8）
      burst_rounds（13644）→ +140（u32，1..60）
      fire_key / fire_key_2（13648）→ +184/+188（u32，choice = fntype）
      第 4 槽 +156 刻意不提供：全表恒 0，游戏也不显示，只在槽 3 的 help 里说明。
 A3 22396 / 22444 桌面桥 rows()：firemode / fntype 的显示文案。
 A4 桌面桥 choices()：firemode 给 0..8，fntype 给 0/2/3/4/8/11，当前值不在表里时补
      「未确认的功能 N（原值）」，不编造语义。
 A5 桌面桥 choose() 接受 firemode / fntype，走 state.desktop.set。
 A6 18481 change() 新增 firemode/fntype 分支：非法值不再假成功，ui.message 显示 allowed.why
      （修的是 offline 分支不夹取、write_field 的 why 被吞掉）。

【B】粘附 / 资源驻留 / 空投舱（fm2）
 B1 15096-15100 投掷物「粘附」分节新增 10 行：sticky_mode(+0)、sticky_flag_a/b/c(+4/+5/+6)、
      sticky_hit_damage(+44)、sticky_hit_effect(+48)、sticky_surface(+52)、
      sticky_ability_a/b(+60/+64)、sticky_param(+72, f32)。tip 统一标「实验性」。
 B2 12283-12412 read_field 新增三种 storage：rackitem / package / entry，
      并统一走 bytes(size)（这样 original_read 也生效）；encode / write_field 同步。
 B3 17633-17900 新增 MOD.refs：hex / names / list_of / items / packages / entries / register /
      stratagem_rows。items 收集 package + loadout 键与 rack 槽里的 8 字节键；
      packages 取 LoadoutPackage 行 +8 的包 id；entries 取 LoadoutEntry 行 +0 的 id。
 B4 17851 stratagem_rows：资源包（+168 / u64 / choice=package）、装配条目（+248 / u32 / choice=entry）、
      空投舱投放件数（+556）、随机挑几件（+552）、槽 1..8（rack + slot*64）。
 B5 14160 / 16145 sentry_payloads：哨戒炮/固定炮走的是 weapon.slot=='Stratagems' 分支，
      不进 resolve_stratagem，于是 add() 里把 payload 键收集到 sentry.sentry_payloads，
      再在哨戒分支按 sentry_defs 调 stratagem_rows（否则新行不出现）。

【C】载具/机甲挂载、座位、阵营、AI 行为、机甲换臂（fm3）
 C1 11781-11785 TYPES 追加 faction 0x5653EA91 / behavior 0xBA9B803D / seat 0x4AEAFC86；
      新增 MOD.MOUNT_SIDE（0 通用/1 右侧/2 左侧）、MOD.FACTION_NAMES（0 继承/1 超级地球/
      2 终结者/4 光明族/8 自动化军团）、MOD.MOUNT_NAMES、MOD.ARM_ORDER（10 个臂件）、MOD.ARM_NAMES。
 C2 KINDS 追加 faction（stride 152 keyed）、behavior（stride 12 keyed）、seat（stride 424 keyed）。
 C3 12308/12368/12412 read_field/encode/write_field 新增 storage 'mountitem'
      （读 8 字节物品键 → MOD.refs.mounts().by_bytes；未知键现场登记，保证可读可写）。
 C4 17745-17800 新增 MOD.ents：mounts()（mount 表每行 ×5 槽 + ARM_ORDER + 武器键，
      label = 臂件名 or 实体名 or 16 位十六进制）、static()、sides()、factions()、
      behaviours()（逐行取 u32(+0) 去重）、pick()、rows(entry, key)。
 C5 MOD.ents.rows 生成四段：
      挂载：槽 1..5（挂载件 / 左右侧），非空槽再加 挂点 A(+8)、挂点名(+16)、标记 1(+20)、标记 2(+21)
      座位：SeatInfo +0
      阵营：Faction +0（choice=faction，allowed {0,1,2,4,8}）
      AI 行为：Behavior +0（choice=behavior）
      用 entry.ents_rows 去重，避免二次 resolve 重复加行。
 C6 接线：resolve_gun 尾、载具 dispatch、敌人分支各调一次 MOD.ents.rows；
      weapon.ents_rows = nil 在换件/预设路径上重置。
 C7 18499 change() 新增 mountitem / mountside / faction / behavior 分支：
      reg.at / reg.by_id 校验，越界写 ui.message 而不是「已保存」。
 C8 22402-22486 桌面桥 rows()/choices()/choose() 支持四类 choice（挂载件 370 项、AI 行为 584 项）。
 C9 offline/zh_params.lua：新增「Fire mode 1..3 / Rounds per burst / Function input 1..2」
      以及 fm2、fm3 各段标签与 hint 共 33 条。

【已知边界】
 - 桌面外壳（Qt 6.8.3 + HuskarUI 的 C++/QML 层）没有源码编译条件，沿用 fm2 载荷；
   本补丁只改 Lua 面板与词典。
 - 挂点名(+16) / 挂点 A(+8) 是游戏内部认挂位的哈希，不同挂位取值不同；
   面板只给已确认的名字，未确认的显示十六进制，不编造。
