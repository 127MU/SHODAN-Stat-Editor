# 已有差异整理与透明条目修复

## 问题与操作入口

部分游戏安装中，多把武器的晃动倍率已被旧工具改成 0，而可信原值为 1。它们在编辑器启动前就已不同，不能把当前文件重新认作原版，也不能仅为了消除标记而隐藏差异。

目录搜索栏下方新增“整理已有差异”。窗口列出当前存储数值对应的逻辑显示值与可信原值，默认只勾选武器晃动差异，也支持清空、全选和逐项选择。确认后生成一次可撤销、会随重启保留的恢复草稿，再由常规“写入游戏”流程生效。

已由编辑器记录的修改会保留；同时保护它们覆盖的相邻字节别名。未选择的数值不变。共享字段会说明影响数量。恢复到可信原值的项目显示“已恢复原值”，不会继续笼统显示“已修改”。

这个操作仅恢复具有可信原值且支持普通数值编码的字段，不修改资源补丁、未知组件或引用类型。护甲被动使用独立的语义身份接口，不能使用旧目录的数组相对偏移批量恢复，因此在本操作中跳过。跳过和保留数量会显示给用户。

## 原子性及防护

- Rust 端 `baseline_cleanup_preview` 只读产生预览。
- `baseline_cleanup_apply` 要求匹配预览指纹及明确选择的字段 ID；过期或越界选择被拒绝。
- 使用 `Workspace::set_batch` 作为一个持久化、可撤销事务，不直接写游戏。
- 默认值读取当前支持版本的认证基线，绝不把现有修改写成默认值。
- 恢复使用原始编码值。例如显示为 1 的 `f32::MAX` 哨兵必须恢复原始位模式，不能把显示值 1 直接写进去。
- 安装及恢复仍走已有备份、校验和冲突检查，不删除其他工具的文件。

## 样式

部件选择弹窗移除 Material Card 的默认不透明浅色填充和阴影，改用当前强调色的低透明度底色、细边框；文字、悬停反馈继续跟随深浅色主题。条目同时区分“已修改”“已有差异（启动前存在）”“已恢复原值”和“原值待核对”。

## 验证

`tests/test_native_baseline_cleanup.py` 在复制的数值文件及隔离配置中模拟其他工具先安装修改，再打开本编辑器，验证干净基线、选择恢复、过期预览拒绝、保留已记录修改、保留未选项、撤销/重做、重启、实际安装及恢复；另外检查恢复哨兵值后的真实二进制位模式。传入的 Steam 目录始终只读。

Flutter 的 `test/baseline_cleanup_test.dart` 验证默认选择、确认后才提交、不自动安装、过期提示及浅/深色条目透明度。完整 Flutter 测试 51 项及静态分析通过；Rust 核心 94 项、便携启动器 1 项通过。

### r5 附件重打包：修正“仅已修改”筛选

已恢复可信原值的参数仍可能有待写入记录。目录筛选现在优先判断 `baseline_state`：`same` 不进入“仅已修改”，`different` 保留；原值未知或旧接口未提供比较结果时，继续保留有修改记录的条目。写入队列和撤销记录独立处理，不因筛选隐藏而丢失。

新增主页、父子分组及搜索回归，验证恢复原值的卡片退出筛选，真实修改仍能找到，取消筛选后仍显示恢复状态。重打包版完整 Flutter 测试 53 项、静态分析通过。
