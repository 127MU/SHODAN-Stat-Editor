# 诊断日志（2026-11-09）

设置 → 日志与诊断 → 开启诊断模式，重新操作一次有问题的功能，再运行只读诊断并导出诊断日志。程序不会自动上传日志，也不会为诊断写入游戏数据。

## 不开启诊断模式也会记录

- 数据引擎启动、退出代码、连接失败和待处理请求编号。
- 打开游戏工作区、写入预览、实际写入、恢复、自动修复及 MCP 启停的开始和结束。
- 请求编号、操作名称、耗时、错误或未完成结果。编号关联同一次请求，耗时使用单调计时器。
- 安装/恢复/修复阶段、阶段内完成数与总数，收到阶段时正在处理的请求编号。
- 慢于 1 秒的接口结果；其他接口仅累计调用数、失败数、总耗时及最大耗时。
- 工作区启动问题、迁移提示、运行目录与游戏目录（导出前脱敏）、参数目录信息。

开启诊断模式后，另记录普通查询和编辑接口的开始/结束。字段定位只保留指定接口的技术字段 ID，不记录输入数值、搜索文字、游戏文字、预设名称、预设内容和 MCP 配置。

## 导出格式

JSON 中 `schema_version` 为 2。保留旧的 `events`、`checks`、`logs` 字段，同时增加：

| 字段 | 用途 |
|---|---|
| `session_id` | 区分本次程序会话 |
| `structured_events` | 分类、操作、状态、请求编号、耗时及有界结果摘要 |
| `operation_stats` | 按操作统计调用数、失败数、累计与最大耗时 |
| `workspace` | 工作区信息、最近一次文件检查及自动修复报告 |

`structured_events.status` 可为 `started`、`running`、`completed`、`not_completed`、`error`、`timeout`、`ready`、`requested`、`closed`。`completed` 只表示对应接口正常返回，不等于已经实机验证游戏效果。

只读诊断除基本运行文件检查外，还调用 Rust `baseline_check`，记录逐个数值文件的原值/打开快照/安装状态、资源补丁登记冲突、草稿冲突和未完成事务。工作区尚未打开时会保留检查失败原因，不伪报通过。

## 隐私、容量和异常

- 用户目录、其他电脑的用户目录、当前用户名、Bearer 凭据和 token/password/secret/API key 等键值会脱敏；嵌套 JSON 也会处理。
- 详细事件最多 1,200 条，旧式事件最多 500 条，磁盘会话日志写入预算 2 MiB。单条错误、集合大小和嵌套深度受限。
- 导出最多附带最近 3 份启动/宿主/界面会话日志，每份只取末尾 64 KiB；可保留上一次异常退出的线索。旧日志导出时再次脱敏。
- 写日志失败不阻断编辑。目录权限、数据版本不匹配、原始备份损坏等仍会如实报告。
- 原生进程退出后会清除旧启动状态，后续可重新建立服务连接；不会自动重放失败的修改或安装请求。工作区需要重新打开，避免在不确定的状态下重试写入。

## 开发复查

- `desktop/morrow/lib/diagnostics.dart`：脱敏、容量限制、结构化事件、耗时统计和导出。
- `desktop/morrow/lib/native_service.dart`：请求编号、计时、进程生命周期及安装阶段。
- `desktop/morrow/lib/backend.dart`：工作区信息、只读文件检查及自动修复报告。
- `desktop/morrow/test/diagnostics_test.dart`：隐私、统计、上一会话日志及容量回归。
- `desktop/morrow/test/native_service_test.dart`：异常退出后新建连接及日志关联回归。

## r5.1 坏表与预设排障

`invalid_numeric_data` 表示数值数据无法解封或解析，应同时记录具体文件与阶段；引擎仍运行不表示该文件可编辑或安装。自动修复使用可信来源恢复后重新打开工作区，无可信来源则保留文件并提示处理。见[安装失败处理](installation-failure-repair.md)。

预设库排障记录操作名称、耗时与失败类型，不应增加预设名称、分享正文、剪贴板文本或搜索文字。分享时使用界面的脱敏导出。
