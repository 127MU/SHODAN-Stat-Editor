# 设置中的自动修复

本地实现版本：4.6.0-r4.2，更新日期：2026-11-08。最新回归及原值补齐记录见 [本轮审查](audit-r41-20261108.md)。

本轮新增数值安装登记修复：当前文件与完整安装前备份逐字节一致时，备份并清理过期登记；已登记文件缺失且备份指纹、密封格式和当前游戏预期哈希均有效时，先补回文件再建立工作区。被其他工具实际替换的文件不自动覆盖，并在结果中列为未解决项。安装失败分类及处理边界见 [安装失败原因与修复范围](installation-failure-repair.md)。

后续修订：自动修复现已接入完全缺失驻留槽位的登记清理。只有主文件、GPU 和 stream 伴生文件全部不存在时才处理；有任何文件存在或无法读取时保留登记交由原检查报告。清理失效来源和受影响的组合登记，保留其他槽位；若后续存在更高编号补丁，在已确认缺失的中间槽位写入空 TOC 并登记为空闲槽位，避免中断后续加载。记录更新及补齐通过已有事务备份完成。这不是恢复原模型、特效或音效，界面要求重新安装对应驻留资源。该路径已在 r4.2 的隔离副本回归中验证；下文较早的测试数字保留为历史记录。

## 用户操作

数值安装因“已被其他工具修改，已停止写入”失败时，结果弹窗新增“强制写入”。二次确认后允许接管过时的数值安装记录，并将实际写入前的文件作为新的事务恢复点。不是跳过版本、数据完整性、打开时快照、资源冲突或并发写入校验；其他错误不会显示该按钮。之后恢复操作回到强制接管前的文件，可能仍含其他工具的修改。该功能不向 MCP 开放；现已包含在 r4.2 的安装与恢复回归中。

完全退出游戏，在侧边栏“设置”点击“开始自动修复”。弹窗展示处理阶段、已完成步骤、提示和剩余问题。完成后关闭弹窗，重新打开需要编辑的分类。导出日志继续使用现有脱敏流程，不自动上传。

初始化失败时直接展示设置页面。侧边栏仍可切换；尚未读取的数据页面显示工作区说明和“前往设置修复”按钮，避免反复调用不存在的工作区。修复成功建立工作区后，分类恢复正常读取。

## 实际处理范围

1. 校验当前游戏版本与参数目录匹配，要求游戏完全关闭。
2. 调用已有的安装事务恢复：只回滚与本程序事务输出指纹一致的文件，恢复前另存备份。发现外部修改时拒绝覆盖该文件。
3. 对无效 JSON、版本或元数据结构不合法的草稿，先保存完整恢复副本，再移除活动草稿。来源指纹不符和偏移失效的合法草稿沿用工作区原有的逐文件隔离流程。
4. 重新读取游戏数据，重建参数表和资源查询缓存。
5. 核对 `derived_stratagem_words`。只有当前载入值已不等于记录中的 `after` 的字才解除管理；仍匹配的记录保留 `before` 恢复信息。配置与活动草稿中的同一元数据同步更新，以免重启再次恢复失效记录。此步骤不修改游戏数值文件。
6. 复查完整资源状态及派生战备生成；仍有冲突时，弹窗明确显示剩余问题，不报告全部修复成功。

## 保留与备份

本功能不猜测游戏原值，不下载或自动替换参数目录，不删除其他 Mod。完全缺失的自有驻留槽位按上述规则修复登记；被替换或部分缺失的槽位保留现有文件及登记并报告。独立的纯数值预览与写入仍按 r4.1 的操作范围检查。

状态目录为用户配置目录中的 `native-game/<游戏路径哈希>/`。损坏草稿的恢复副本命名为 `draft-recovery-<完整 SHA-256>.json`。派生配置及草稿修改、无效草稿移除使用已有安装事务：原始字节保存在 `transactions/<事务标识>/*.original`，事务日志记录对应目标。恢复副本已经存在但内容不同会停止处理，避免覆盖。

格式损坏的派生配置、无法读取或超出限制的草稿、未知版本和外部 Mod 内容冲突均不通过清空数据强制修复。错误会返回到弹窗，用户仍可导出诊断。

## 代码入口

- `desktop/morrow/lib/main.dart`：设置入口、启动失败页面、侧边栏可用状态。
- `desktop/morrow/lib/install_dialog.dart`：复用现有玻璃进度弹窗，显示修复阶段和可滚动结果。
- `desktop/morrow/lib/backend.dart`：调用原生修复接口并记录诊断。
- `rust/core/src/native_api.rs`：`game-repair`，包括正常打开失败后的重新建立工作区。该操作不向 MCP 开放。
- `rust/core/src/game_workspace.rs`：修复编排、事务备份与复查。
- `rust/core/src/extra_stratagem.rs`：按加载值核对派生记录。
- `rust/core/src/workspace.rs`：草稿结构校验与保留其余内容的元数据更新。

## 验证结果

- Flutter 分析无问题，37 项界面测试通过，包括正常启动及启动失败后的进度、结果、侧边栏切换和修复后重新打开装备。
- Rust 82 项测试通过，包含禁止从 MCP 执行自动修复。
- 原生接口完整回归使用游戏数据的隔离副本，真实游戏目录只读。新增场景验证失效派生记录导致预览失败、修复后预览成功、保留匹配记录和未安装的数值编辑、旧配置备份字节一致、重复修复、损坏草稿导致启动失败以及修复后的重新打开。
- 额外复现缺失的驻留槽位 121：原登记和实际文件保持不变，报告剩余资源问题，纯数值预览不被阻断。
- 本地 Windows release 构建通过。没有启动游戏验证其他电脑上的实际 Mod，也没有发布发行版。
