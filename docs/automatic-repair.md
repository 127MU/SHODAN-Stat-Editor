# 设置中的自动修复

适用：4.6.0-r5.1 dev；更新：2026-11-09（香港时间）。完整错误分类见 [安装失败处理](installation-failure-repair.md)。历史版本的测试数据见对应审计记录，不作为本版验收数字。

## 用户操作

1. 完全退出游戏和其他编辑器。
2. 在「设置 → 自动修复」点击「开始自动修复」。即使初始化失败，也可进入设置；尚未载入的分类会显示工作区说明。
3. 查看进度、已完成步骤、提示和剩余问题；完成后重新打开需要编辑的分类。
4. 修复不等于重新应用参数。保留的草稿、预设和护甲选择仍需核对，必要时点击「写入游戏」。
5. 结果仍有问题时导出诊断日志；日志仅保存在本地，导出会脱敏。

## 实际处理范围

| 检查 | 处理 |
| --- | --- |
| 游戏版本 | 对照目录的 game_build 与 game.dll；不猜测未知版本布局 |
| 中断安装 | 按事务指纹恢复，保留备份；目标再次变化时报告冲突 |
| 无法解析的数值表 | 普通打开时隔离并标出文件名，其余表可浏览；自动修复先保存坏文件，再优先使用匹配当前版本的已校验安装备份，否则使用固定指纹的随附原版表 |
| 缺失的受管数值文件 | 备份完整、SHA-256/密封格式/当前版本哈希有效时补回 |
| 数值安装登记过期 | 当前密封文件与安装前备份逐字节一致时清理旧登记，不覆盖有效的外部修改 |
| 损坏草稿或安装配置 | 先完整备份，再解除无法解析内容的启动阻塞；合法但来源变化的草稿仍按文件隔离 |
| 失效派生战备登记 | 解除与载入值不一致的派生记录；保留仍匹配记录的恢复信息，并同步配置和草稿 |
| 完全缺失的自有驻留槽位 | 核对主文件及 GPU/stream 伴生文件均不存在后清理登记；必要时在已确认的中间缺号补空 TOC，保留后续加载链 |
| 缓存与索引 | 重读游戏数据和草稿，刷新参数、资源及文字查询缓存，再检查剩余问题 |

### 坏表与可信恢复来源

`解密数据的 LDLD 结构无效` 与“原值未知”不是同一问题。前者表示文件不能按当前格式解析；后者表示当前值可能可读，但原版来源无法可靠确认。

桌面工作区隔离坏表时，不会把原版数据冒充为当前值，也不会允许坏表通过安装校验。自动修复要求恢复来源匹配当前版本；没有可信来源时保留现状，提示通过 Steam 验证游戏文件完整性。结构有效的其他 Mod 不会仅因数值不同而被自动还原。

## 强制写入和强制恢复

r5.1 中，安装失败、预览异常或预览受阻都提供「强制写入」入口；恢复失败提供「强制恢复」入口，不再依赖某一句错误文本。

强制写入接管冲突数值登记前会备份实际当前文件；之后恢复可能回到仍含其他工具修改的状态。校验空间不足时，强制写入允许已修改浮点参数的极小校验修正，结果以实际修正值为准。明确输入整数不需要人为补小数位。

强制操作仍需有效表结构、匹配版本、有效恢复源、可写磁盘和成功备份。权限不足、文件占用、损坏备份不会因按钮名称而消失，也不会显示虚假的成功结果。自动修复与实际安装/恢复只从桌面入口执行，不向 MCP 开放游戏写入权限。

## 备份与保留

工作区位于配置根下的 `native-game/<游戏路径指纹>/`。安装和恢复备份保存在 `transactions/<事务标识>/*.original`，草稿恢复副本使用 `draft-recovery-<SHA-256>.json` 等名称。不要手动删除备份或清空登记来绕过检查。

部分缺失或被替换的资源补丁仍会报告；清理登记和补齐空槽不能恢复原模型、特效或声音，需要核对后重新安装资源。原始数据、权限或版本无法确认时，自动修复会留下未解决项。
