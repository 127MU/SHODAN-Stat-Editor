# r4.1 安装及游戏参数复查（2026-11-08）

本轮基于已合并 PR #47 的源码。后续修改按用户要求必须通过测试后交付，未修改真实游戏目录。

## 已定位并修正

- 强制恢复将不存在的文件当成空文件，事务比较 `Some([])` 与磁盘 `None` 不相等，仍然无法恢复。现在保留缺失状态，只把 NotFound 视为缺失；读取失败不允许强制覆盖。回归实际执行创建事务，而非只校验读取函数。
- 自动修复弹窗重复输出 warnings，已去重显示。
- 新的无 fontTools 图标修复脚本未接入正式包校验。现在打包校验在缺少 fontTools 时调用 Flutter SDK 的字体子集工具。
- 准星选择项把类型字段写成 1/2；改用已识别的类型 0（通用）、3（隐藏）、4（步枪）和 16（锁定样式）。准星样式不会自动授予武器锁定能力。
- 植被忽略碰撞仅覆盖旧名单中的火箭及战备弹药。扩展到参数目录中主武器、副武器、支援武器和投掷物绑定的射弹，同时保留旧版已验证目标。只转换原有模板 0 到 3；不能保证穿过树干等独立实体。
- 开关重复开启时，已经处于目标状态的版本配方可能错误报告无可用字段。现在保持幂等，并保留本次接管的字段列表，关闭仅恢复这些字段。
- 驻留组合状态只看文件存在，未确认登记指纹。现已核对 TOC/GPU/stream 全部登记指纹，外部替换不会被继续报告为正常已安装。
- 窗口顶栏移到页面、玻璃背景和主题揭幕动画外层，使用实色底层，不再参与页面动画和背景合成。
- 布娃娃开关改成草稿配置，加入写入预览，随数值修改一起安装及恢复；切换时不立即写补丁。仅元数据修改也会标记待写入。
- 补齐五张缺失的可信原值表：护甲条目、实体增量、状态效果、拆毁和光束。来源先按 Steam depot 553853 / manifest 87932884035420122 的文件长度和完整 SHA-1 核对封包，再用原生服务解密并固定明文 SHA-256。证据保存在 `offline/originals/depot-baseline-evidence.json`，不包含本机路径。未通过 depot 指纹的当前文件不会导入。
- 常驻资源和状态机的补丁操作控件补充逻辑默认状态“未安装”。这些不是游戏数值，旧的空默认值会使拥有该控件的整个装备被误判为原值待核对。
- 战备表的随附原值仍是旧文件（82,384 字节），当前版本门禁不接纳，造成冷却、次数、战备指令、投送倒计时、附赠战备和资源包约千条参数缺失原值。换成 depot 匹配的 82,376 字节原始表，并同步原值 build 标识及 Rust 指纹白名单。其余已随附表和嵌入被动表亦与 depot 封包逐一交叉核对。

## 可重复复查

`tools/audit_native_baselines.py` 使用临时独立配置目录，经真实桌面 RPC 遍历整个参数目录，输出全部缺失原值和读值错误，且不安装或恢复游戏文件。不是只抽样查看一个武器。

`tools/import_verified_baselines.py` 是开发工具，要求指定 Steam manifest 的固定 SHA-256，只接纳与该 manifest 中封包长度和 SHA-1 完全一致的文件。输出仍需加入 Rust 端明文指纹白名单，避免用户任意替换随包原值。

## 保留字节与安装失败

文件内校验保留区长度由格式规定，不能任意增大。现有校正会在每次求解前重新清零保留区；非零校验字节并不表示容量被永久消耗。本轮把备用头部候选从 16 位范围扩展至 18 位范围（约 4 倍），使用既有保留区的三个字节，不增加文件长度，不改有效载荷布局。

连续测试另复现了整数开关无法安装的真实原因：部分射弹文件只有一个数据块，没有第二个头部用作校验盐，且整数修改没有可借用的已修改浮点字段。仅增加搜索范围不能解决。

对于这种单块、确实存在待写入字节、且没有已编辑浮点字段的射弹文件，写入预览会说明可借用一个类型为 ProjectileInfo、偏移 +32 的已知初速字段作微小校正。候选必须有限、为正且不在 f32 上界；修改仅用于本次封装副本，保留文件结构、保护区、哈希及加密回读校验。安装结果列出实际校正值。其他未修改文件不参与，未确认写入不执行校正。
