
# 资源驻留与状态机补丁

本文说明 4.1.0-r22 新增的两项能力背后的机制：**资源驻留**（让一个资源包常驻内存）与**状态机补丁**（让挂在载具槽里的炮塔、工事真正展开）。文中数值来自社区在游戏 build **26088801** 上的实测记录，换 build 需要重新核对；编辑器里的自动配方不依赖这些编号。

## 一、两层机制

游戏把资源装在「包」（package）里。某个资源要在运行时真正生效，需要同时满足两件事：

| 层 | 由什么决定 | 我们的改法 |
| --- | --- | --- |
| 这个包在不在内存里 | 资源声明口 | 把包整体并进 `data/<宿主包>.patch_N` 这条补丁，让它跟着宿主包一起加载 |
| 这个资源在不在包里 | 包自身的条目 | 在同一条补丁里放改后的字节 |

一句话：**声明口管「包在不在」，补丁管「资源在不在」**。两者混为一谈，就会出现「改了但没效果」或「紫问号」。

## 二、资源驻留

### 载体包

补丁挂在哪个宿主包上，决定了它什么时候进内存：

| 宿主包 | 身份 | 适用 |
| --- | --- | --- |
| `9ba626afa44a3aa3` | boot 包（settings.ini 的 boot_package），4052 条 | 默认。开游戏就加载，资源永远在内存里 |
| `f6fb08cc02d24255` | 共享基础包，782 条 | 想跟上界面加载节奏时可用 |
| `bca0ea9bbcb1a2f0` | pre_boot，2 条 | 更早，但能挂的东西少 |
| `495cd5b6043a104d` | fallback，25 条 | 兜底 |

### 三种模式

- **完整**：把整个包写进补丁，含贴图、网格、动画等全部内容。代价是体积与内存，尤其是贴图会占用流式池。
- **仅轻资源**：跳过贴图与流式资源，只带元数据。体积小，但缺少贴图的模型显示为白模。
- **移除**：删掉这条补丁，并把后续槽位前移保持连续。

换模式不需要先移除：写入时会复用同一槽位重建。

### 四条铁律

1. **序号必须连续**：`patch_0`、`patch_1`、`patch_2`……中间缺号，后面的补丁会被静默忽略。
2. **同一资源编号以序号更大的补丁为准**：所以「这条补丁只改一处、其余靠另一条补丁继承」是行不通的，每条补丁都要自带它需要的全部字节。
3. **伴生文件要一起写**：带 GPU 或流式资源的条目必须同时提供 `.gpu_resources` 与 `.stream`，缺了会白模或紫问号。
4. **挂载路径不加载挂件自己声明的包**：这是紫问号最常见的来源，也正是资源驻留存在的理由。

### 内存

索引登记会累积，toc 元数据随补丁体积增长，GPU 资源走流式池并受 `texture_streaming.memory_budget_mb`（默认 1536）驱逐。省内存的办法是只放必需的条目——例如只放一条 4 KB 的状态机，而不是整包。

## 三、状态机补丁（炮塔与工事）

### 为什么挂在载具槽里的炮塔不展开

正常流程里，炮塔会跑一遍部署动作。被当成载具挂件用时，它不走这条路，而是直接停在自己状态机资源**第一层的默认状态**上，也就是折叠态。所以要改的通常只是一个 u32：某层（layer）的 `DefaultState`。

### 判据

1. **看第一层有没有独立的「展开态」**：状态名 `0x823905BD6B62BA3E`。有 → 把默认状态指过去即可（模板 A）。
2. **没有展开态**：把第一层钉到「部署过渡态」（一般为索引 1）。该状态 `loop=0` 且无出口，引擎会保持末帧，视觉上就是展开（模板 B）。
3. **关掉扫视层**：该层同时含扫描 idle 状态 `0x9EA750D5873EB183` 与 `Empty` 状态 `0x86342D705E08AD12` 时，把该层默认状态改成 Empty 的索引。不关的话，扫视动作会把握好的姿态卷回折叠。
4. **人操工事的可控轴**：只有位于「默认开启的 Time/Blend 层 + 有按键 clip」的轴才受输入控制，改状态机不改变这一点。
5. **改完自检**：整个文件只应变更 1～2 处；多于此说明配方套错了模板。

### 编辑器怎么做

哨戒与工事页面的「状态机」一栏不需要你记住上面任何编号：

- **状态机资源**：列出该装备资源包里的状态机条目（一个包里可能有两三份，例如迫击炮的气体与电磁），选择要改哪一份。
- **炮塔展开（状态机补丁）**：写入或移除。写入时程序解析状态机、按状态名套用上面的判据、生成改动预览，并做幂等与自检；改动超过两处会在说明行提示。

写入位置与资源驻留相同（`9ba626afa44a3aa3.patch_N`）。如果该包已经有驻留补丁，程序会复用同一槽位重建，把状态机字节嵌进去，避免两条补丁抢占同一资源编号。

## 四、使用顺序

1. 关闭游戏。
2. 在该装备页面确认资源包（`资源包（+168）`）不是空的；挂载件本身不加载自己声明的包时，先把资源驻留设为**完整**。
3. 选择状态机资源（多数装备只有一份，不用动）。
4. 把「炮塔展开（状态机补丁）」设为写入，核对说明行的预览。
5. 启动游戏查看；不需要展开时设为移除即可恢复。

## 五、排障

| 现象 | 常见原因 |
| --- | --- |
| 改完仍是折叠姿态 | 没重启游戏；或状态机指向了扫视层，被扫视动作卷回；或挂载路径没有加载这个包 |
| 紫色问号 | 资源包没有驻留，或驻留补丁序号不连续被忽略 |
| 白模 / 无贴图 | 驻留选了「仅轻资源」，缺少贴图与流式资源 |
| 说明行提示「不需要改」 | 该状态机第一层默认状态已经是展开态 |
| 写入被拒 | 游戏还在运行；程序会拦下并要求先关闭 |
