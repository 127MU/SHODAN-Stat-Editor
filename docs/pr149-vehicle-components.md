# PR #149 载具组件适配

上游变更：[SHODAN-HORAI/SHODAN-Stat-Editor #149](https://github.com/SHODAN-HORAI/SHODAN-Stat-Editor/pull/149)，核对的提交为 `202e2c78a9d6d3647a3d2f5ff4c1637edcea5a55`。

## 可用入口

载具与机甲 → 选择载具 → 打开参数分类。新增分类沿用现有参数弹窗、搜索、修改记录、撤销、预设、MCP 和统一写入流程。

- 燃料与引擎：初始油量、容量、怠速/全油门消耗、油箱受损泄漏、启动时间、低油量警告、快速下车动画阈值。
- 车轮悬挂：逐轮长度、驱动开关、触发阈值、骨骼及动画变量哈希；每个轮槽分别修改，不对多轮取平均。
- 载具效果：扬尘、落地、导航视线、界面资源、状态与悬挂效果冷却。
- 座位：乘员入口、上下车行为、继承速度、销毁行为、车门、车内战略配备、武器收起、名牌和音效。
- 驾驶响应：加速度、摩擦、受损引擎/变速箱/车轮倍率，以及转向、油门、刹车响应。
- 碰撞伤害：对外伤害、自损、拆毁、击退、速度阈值及伤害类型。

保留原来的完整 64 位挂载实体选择器及左右侧设置；没有重复添加高低位实体控制。已有挂点字段也不重复添加。原始记录不存在的组件不显示、不自动制造。

这些新增组件的游戏内效果尚未实机验证，参数分类已标注实验性；字段定位和文件读写通过离线验证。速度阈值和响应速度并不等同于最高车速；哈希字段也不是可任意增减的普通数值。

## 与上游实现的适配差异

当前支持的数据版本使用以下外层 LDLD 表编号：

| 组件 | 外层表类型 | 每条记录字节数 |
| --- | --- | --- |
| 载具 | `EAEB2B0D` | 3704 |
| 挂载 | `3845B1E0` | 120 |
| 座位 | `4AEAFC86` | 424 |
| 驾驶运动 | `83B65443` | 456 |
| 碰撞伤害 | `20288698` | 208 |

`48F7C789` / `76CC175E` 是内部组件类型，不是当前文件的外层表编号，不能直接拿来索引 LDLD 块。可信原始文件中实际解析出 14 条驾驶运动记录和 14 条碰撞伤害记录。

空轮槽也有 1.0 的默认悬挂长度。仅按长度为正判断，会把机甲显示成 32 轮。清单根据可信原始数据中的骨骼绑定或非空槽悬挂配置生成：FRV 为 4 槽，履带载具与采集钻机为 10 槽，四种外骨骼不添加空轮槽。

`vehicle_inventory.json` 只保存稳定实体标识、组件存在性和有效轮槽编号，不保存物理默认值。当前文件被其他工具修改后，也不能被此清单当作原版数值。实际原值继续由既有可信基线读取逻辑提供。

## 维护与验证

实现：`rust/core/src/catalog_vehicles.rs`；表布局：`rust/core/src/tables.rs`。

重建清单时，先运行 `shodan-native tables offline/originals/generated_entities.dl_plain` 保存表索引 JSON，再运行：

```powershell
python tools/build_vehicle_inventory.py <表索引JSON路径>
```

生成器会检查原始文件 SHA-256：`dc6d52a14900942b2f59f56bf8ab1552259832202dcb0745c3c84a009ff5f98b`。其他游戏版本必须重新核对布局，不能只放宽此断言。

回归脚本：`tests/test_native_vehicles.py`。脚本复制数值文件、只读引用资源包，在隔离目录验证：

1. 默认值来自可信原始文件。
2. 有效轮槽与缺失组件过滤。
3. 浮点数及负值按照 f32 编码，而非整数位模式。
4. 一字节开关不会覆写相邻标志。
5. 新参数的全局预设导出、导入和读取。
6. 实际封装、安装、重新解密后的物理字节。
7. 恢复后与安装前密文逐字节一致。

脚本不修改传入的 Steam 目录；实机驾驶、碰撞和乘员行为仍需用户在游戏中确认。

本次离线结果：93 项核心单元测试与 1 项便携启动器测试通过；载具专项的 8 组参数、预设往返、实际安装及恢复通过。完整目录检查 1983 个条目、71811 个参数，原值未知 0 项、解析错误 0 项；原有桌面安装/修复/恢复回归也通过。
