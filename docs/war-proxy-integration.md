# 变种（实验性）

侧边栏的“变种”页面使用上游 [mitmproxy](https://github.com/mitmproxy/mitmproxy)
的 `mitmdump` 核心，代理与变种共用开关，不再需要 `variant_mod`。
默认关闭，不随编辑器启动，也不参与数值修改的“写入游戏”。

握手采用 `connection_strategy=lazy`、`upstream_cert=false`：先用本机 API 证书完成客户端 TLS，收到实际请求后再连接上游，避免上游证书探测阻塞游戏握手。此选项不关闭上游服务器证书验证。参见 [mitmproxy 选项说明](https://docs.mitmproxy.org/stable/concepts/options/)。

## 使用

1. 在“编辑方案”选择星球，点击“选择 / 搜索效果”打开勾选弹窗，再保存方案。高级阵营与战役设置默认收起；“已保存方案”用于切换、导入导出；证书与启动配置集中在“连接设置”。
   内置 273 颗星球与 70 项研究效果快照。快照不等于当前战争目录。
2. 关闭游戏，开启变种。默认使用 HTTP 代理兼容模式，监听随机本机端口；
   仅 `api.live.prod.thehelldiversgame.com:443` 进入 mitmproxy；仅在连接设置开启“游戏 API 经现有 HTTP 代理转发”时，才将当前系统 HTTP 代理用于 API 上游；默认不串联 HTTP 代理，按 Windows 网络路由连接。加速器与 TUN 的接管范围由其自身规则决定。此设置不会更改网络工具配置，不修改 hosts 或系统代理。
   Steam 子进程仍携带显式代理环境，连接先经过本机分流入口；所有其他 CONNECT 目标保持端到端 TLS 并直连，普通 HTTP 也直接转发，不经变种上游、不保存流量。它不是系统级或全进程网络接管。
   `allow_hosts` 限定游戏 API 域名。默认包仅提供此模式，排除 WinDivert 驱动、DLL 和进程重定向辅助程序。
   旧配置中的进程捕获模式自动切换为 HTTP / Steam 桥接；不再提供需要捕获驱动的入口。
3. 首次使用点击“初始化并安装本机证书”，先在隔离的本机随机端口生成 CA，
   随即退出初始化代理，再调用 Windows 证书工具，
   不弹安装向导，安装范围仅为当前用户的 Root 存储。不会启动时自动信任，
   不会随程序分发 CA 私钥。“打开本机 CA 证书”可查看证书。
4. 首次点击“复制 Steam 启动选项”，在 Steam 库右键游戏 → 属性 → 通用 → 启动选项中粘贴。
   已有选项请先备份，原有游戏参数可保留在 `%command%` 后。程序不会修改 Steam 配置文件。
   桥接程序安装在本机用户配置目录，不依赖某次 EXE 解包缓存。
5. 等待代理和证书就绪，点击“通过 Steam 启动游戏”，也可直接从 Steam 库启动。
   桥接保留 Steam 原始命令、参数和工作目录，只为新游戏进程设置代理环境。
   PlayFab 与已知 Easy Anti-Cheat/Epic 域名通过 NO_PROXY 绕过本机代理及分流器，保留游戏进程原始连接路径，原有 NO_PROXY 条目保留；不更改系统网络设置。
   启动前检查本机代理 TCP 端口，端口不可连接时提示并中止启动。开启代理时自动更新已经安装的桥接文件，避免升级后继续执行旧桥接。
   已运行的游戏不会自动接管。是否接入以页面连接计数为准。
   状态依次区分进程启动、插件加载、服务就绪、收到效果目录和实际响应改写。
6. 关闭变种或关闭编辑器停止代理；重启游戏恢复原始在线战况。
   桥接检查代理进程 PID 和创建时间，过期会话不添加代理环境；也可删除 Steam 桥接启动选项恢复普通启动。

方案参数持久保存；启用状态不会在重启时恢复。效果选择不会自动改变星球归属，
只有明确启用的实验性阵营覆盖才会改写归属与对应战役阵营。

“作战敌人”可在高级设置中独立选择（`campaign_race`，0 为自动）。自动模式优先保留原始战役和原始敌对归属；已解放星球若包含已确认的原生生化人效果 #1361，则新建战役使用机器人阵营。超级地球归属不会再强制回退为终结族。只有原服务器效果参与原生阵营推断，用户添加的跨阵营效果不参与。此修正只校正战役元数据，不保证任意事件效果组合都有客户端可生成的任务模板。
停止代理不会撤销客户端已缓存的战况，因此仍需重新登录。
“卸载本程序证书”仅按记录的完整指纹移除本程序安装的 CA，不按名称模糊删除。

## 改写范围

代理使用本机 CA 签发仅供本次会话的 API 证书，包含可查询的吊销列表地址。
列表由同一 CA 签名，仅在随机本机 HTTP 端口提供固定 CRL 内容，关闭代理时停止服务。
保留客户端吊销检查及上游 TLS 验证。证书和 CA 私钥仅保存在本机用户配置目录。

仅处理游戏 API 的 GET `GalacticWarEffects` 与数字战争编号的 `Status`。
必须先收到本次游戏提供的有效效果目录，随后才向 `planetActiveEffects` 添加条目。
目录全量接入：按名称、原名、ID 搜索，按敌情、战备、装备、词条等类型筛选。
游戏文本中可定位的名称和说明使用本机语料；描述性译名单独标明，未测组合标实验性。
“仅转发并采集目录”不会应用保存的方案；只缓存公开效果字段和星球编号、归属、玩家数量，
不缓存账号、认证头或完整响应。当前会话验证不使用旧缓存放行效果。
重复条目去重；未知效果、未知星球、结构变化和无效响应都保持原样。
默认仅添加效果。按星球可单独开启实验性的敌人阵营/归属覆盖与战役开放、类型覆盖。
已有战役保留编号与其他字段，新战役分配无冲突且在会话内稳定的编号。
星球开放会使客户端可能向线上服务器创建作战，奖励与统计兼容性未确认。
不提供仍会报通讯错误的防守事件注入，不修改请求、账号或认证信息。

最多保存 64 颗星球、每颗 32 个效果。方案可分别启停、导入导出、撤销上次保存，
运行时保存会原子更新配置，后续战况按新方案处理；客户端缓存仍需重新登录清除。
JSON 方案验证失败时不会部分应用，其他工具改动不会被自动清理。

运行时每 250 毫秒检查方案内容摘要，只有成功处理下一次游戏 Status 响应才确认“本次方案已写入响应”。
仅移除游戏战况 GET 请求的条件缓存头，防止 304 绕过新方案处理；不修改认证或作战创建请求。
游戏不主动刷新时仍需退出星图或重新登录；不承诺重建已生成的作战，也不热改正在进行的任务。
13 组经核对的 type40 星图词条/type71 presence 配对会一起添加，且双方必须在本次目录中、类型匹配。
无法据此把所有图标/文案效果变成实际玩法。现有战役 count 为零时开放操作会将其恢复为 1。
效果组合是否有可用作战取决于客户端任务模板，当前不保证任意组合均可游玩。
`campaign-diagnostics.json` 只保留目标星球的战役结构和效果 ID，用于区分已写入响应和任务池可游玩状态。

效果目录优先采用用户提供的资源 ID 对照表，保留“图标”等限定及额外备注。
当前对照表可为本次 310 项目录中的 280 项提供名称；未匹配项继续用可定位的游戏文本或明确标记名称待核对。
译名绑定目录内的效果类型和名称哈希，防止未来重复利用 ID 时误贴旧名称。

代理使用 Windows Job Object 跟随编辑器生命周期，并使用配置锁拦截同一配置的重复启动。
正常关闭先通知上游核心释放捕获，再进行超时清理；启动插件超时会停止并报告。
状态轮询区分启动等待、短暂读取失败和持续失联；首次尚未生成 health.json 时不再直接报文件错误。
读取只接受本次会话且 15 秒内更新的状态；短暂不可读自动重试，连续 15 秒没有有效状态时撤销新的 Steam 桥接启动资格，文件恢复后自动重新核对。

游戏若拒绝代理证书，或进程捕获不兼容，此路线将无法工作；不关闭 TLS 上游校验，
不绕过证书固定或反作弊。尚未实测当前游戏完整登录与局内效果。

研究样例 1373/1386 来自 warId 801，不能视为未来战争的固定目录。
机制资料：[hd2-network-proxy](https://github.com/deepseekv41flash/hd2-network-proxy)。

## 本地打包

### 原生分区开放实验

旧方案字段 `open_regions` 默认为 `false`，保留解析兼容；界面不再提供该测试开关。
它只修改本次 Status 中目标星球已有的 `planetRegions`：将 `isAvailable` 设为真，
将非正的 `availabilityFactor` 设为 1；保留其他正值、归属、生命值与分区编号。
不生成分区、不改写 WarInfo 地形定义。缺少分区或字段类型不兼容时，跳过分区实验，
仍应用独立的战役和效果配置，并在诊断文件中记录 `region_error`。
诊断文件记录目标分区改写前后的可用状态；该选项尚未经过可玩作战的实机验证。

`initialize_regions` 是独立的分区状态初始化实验，默认为 `false`。
开启时必须同时开启战役并明确选择敌人（终结族、机器人或光能族）。
插件异步读取官方公共 WarInfo，按战争编号和布局版本匹配并缓存分区定义；
没有匹配定义时跳过分区实验，仍处理原有战役配置。
只为原生定义中缺失的分区补充 Status 状态：所选敌方归属、原生上限 50% 生命值、
玩家数和恢复率为 0、`isAvailable=true`、`availabilityFactor=1`。
这些是实验初始化值，不能显示成服务器原值；已有分区完整保留。
只有另外开启 `open_regions` 才会调整已有分区的可用状态。
读取公共定义最多等待 8 秒，在线程中执行；不发送账户凭据、不调用作战创建或奖励接口。
当前战争 801、布局 717 的超级地球和生化斯坦已由用户确认可进入作战；其他星球、未来布局和任意效果组合仍未全部验证。

便携 Python 若带有由 `ssl.py` 读取的伴随 CA 策略文件，两者必须作为真实文件一起打包，
不能让 OpenSSL 从标准库 ZIP 内的虚拟路径读取证书。构建器保留该策略文件与原有 TLS 校验；
运行时生成和桌面打包均创建验证型 SSLContext 自检，避免分区定义下载因缺文件而静默回退。

默认使用独立 CPython 3.12 与上游 mitmproxy 12.3.1 源码包，避免嵌套官方单文件核心
在此环境中出现的压缩包读取失败。用户无需单独安装 Python，其他组件许可随运行时保留。

1. 在独立 staging 目录执行 `pip install --no-compile --target <staging> mitmproxy==12.3.1`。
2. 使用 `tools/build_proxy_runtime.py --python-root <CPython目录> --site-packages <staging> --output <运行时目录>`
   生成隔离路径配置、标准库 ZIP、源码入口与逐文件哈希清单。排除测试、字节码缓存与无用命令行启动器。
3. 使用 `tools/package_huskar.py --proxy-runtime <运行时目录>` 加入编辑器，逐文件核验后打包。
4. `tools/package_onefile.py` 会把 manifest 中的运行时一起纳入单 EXE。

仍可用 `--mitmdump <官方程序> --mitmproxy-license <LICENSE>` 构建兼容包，两种方式互斥。

### 防守战役（实验性）

在「变种工作区 → 编辑方案 → 高级设置」开启战役，选择「防守战役」。
目标归属须为超级地球，明确选择作战敌人，再通过可搜索的星球选择器指定进攻来源。
插件只接受本次 Status 中存在且归属与敌人阵营一致的来源星球。
可设置入侵等级、防守时长和战役计数；默认分别为 20、48 小时、38。

根据 [DEFENSE-FORGE-RECIPE](https://github.com/deepseekv41flash/hd2-network-proxy/blob/master/docs/DEFENSE-FORGE-RECIPE.md)，
在同一次 Status 改写中补齐超级地球归属、敌方攻击边、type=4 战役、eventType=1 事件和联合作战。
事件关联战役 ID，事件与联合作战 ID 一致；最大生命值为等级 × 50,000，剩余值设为 99%，potentialBuildUp=0。
事件编号避开已有记录，保留其他星球数据；结构或来源校验失败时保留原响应。
同一代理会话中刷新战况不延长截止时间，重启代理后重新初始化计时。
这套逻辑只改本机响应，服务器不会推进本地防守进度；本项目目前只完成离线验证，实机作战仍需确认。
