# Rust 数据核心重构

4.6.0-r1 已独立发布。后续迁移继续在本地开发分支进行。按最新要求，Flutter/Morrow 界面保留，界面之外的解析、编辑、预设、资源补丁、安装恢复及诊断逻辑全部迁移至 Rust，最终不保留 Lua 运行依赖；当前发布包仍含兼容核心。

## 当前完成

- 原生多文件工作区已支持 8/16/32 位整数、浮点、布尔值、位掩码和完整 64 位资源身份。批量修改与编辑状态共同撤销，导出前核对全部源文件快照。原值来自独立校验的基准文件。
- 已接入配件增量、护甲条目、状态修饰项、拆毁模板及独立档案资源。目录生成工具在隔离配置中提取声明式参数描述，产物约 1.8 MB，支持中文名称、同名字段独立标识和时间换算。运行时使用 Rust 读取实际数据文件。目录生成和旧版对照测试仍使用旧引擎。
- 按具体护甲分配被动的原生预览和成对导出已经实现。37 组护甲及被动文件与旧引擎逐字节一致。
- 当前分支回归覆盖 72 项 Rust 单元测试、66,544 个字段、68,473 个可立即读取的参数行。字段与参数行均通过旧引擎对照。另有 969 行资源状态需要资源事务，旧界面会延迟读取这些状态。
- 原生资源包读写已迁移：F0000011 目录、完整 64 位资源身份、未知元数据保留、TOC 16 字节与 GPU 64 字节对齐、伴生流重建和三文件事务导出。独立测试逐字节比较旧构建器的 TOC/GPU/stream。
- 原生 DSAR/LZ4 与 bundle-set 跨片读取已实现；当前本机游戏只读核对 9725 个包身份、3 个目录，抽样包的 light/full 构建指纹与旧引擎一致。支持纹理异常流长度、unit/bones 流排除及 typed overrides；轻量或单资源模式遇到伴生流会拒绝。
- 当前值引用链已提供原生单会话和跨文件接口：射弹/爆炸/伤害/状态/电弧/激光分开命名空间，循环和重复引用只展开一次，缺失记录明确标记，限制 512 边/24 层。68 条跨文件引用边与旧图遍历和独立字节解析一致。
- 原生驻留规划：兼容 `residency.txt` 四列/五列格式，拒绝重复所有权和路径注入；枚举全部实际槽位，不硬编码 248。孔洞、仅有伴生文件、非规范编号和不可访问路径均不作空槽处理；状态核验只读目录和文件长度，识别 TOC/GPU/stream 越界，不加载整个大型补丁。`residency-plan` 只返回规划，不写入游戏。
- 原生资源扫描与来源选择已接入 `resource-scan/resources-resolve/dependency-closure`：完整 u64 身份、四字节对齐候选扫描、完整索引发布、缓存、循环去重、显式缺失项、稳定来源选择。Wwise HIRC 事件目录用于匹配音效来源，不读取 DATA 音频内容；真实游戏 bank 的事件与独立字节解析器核对一致。哈希命中仍是候选引用，不将其宣称为完整语义依赖或全部声音播放链已验证。
- 原生可选 MCP：`mcp-start/mcp-stop/mcp-status/mcp-config`，默认关闭，随机令牌、仅监听本机、拒绝跨来源浏览器请求；工具调用与原生标准输入接口共享同一会话，已验证跨接口修改和撤销。仅公布已实现的 Rust 接口，尚未连接兼容版 Flutter 会话。
- 原生异步更新检查：`update-start/update-poll/update-parse`，保留发行说明、支持修订号、校验本仓库下载地址；GitHub API 失败后尝试现有 GH-Proxy 公开元数据镜像，不发送令牌。Windows HTTPS 使用系统 WinHTTP，不更改代理或证书配置。本机网络检查成功读取正式版 `v4.6.0` 的 749 字更新说明与下载地址。
- Flutter 已通过独立 `NativeService` 接入原生更新接口：启动自动检查一次、设置内手动检查、更新日志弹窗、发行版/下载链接均不走 Lua。IPC 并发启动、中文往返和关闭已在只含原生 EXE 的隔离目录验证；正式打包同时包含 `shodan-native.exe`。编辑业务尚未切换，MCP 不会连接另一份兼容编辑状态来伪装为共享会话。
- 本轮验证：61 项 Rust 单元测试、23 项 Flutter 测试通过；优化构建后的原生接口、MCP、更新、驻留、真实兼容宿主被动保存/重载及六份数据的哈希修正/密封导出回归通过。资源、修改和安装相关测试只写隔离目录，不安装游戏。构建体积使用尺寸优化、Thin LTO 和单代码生成单元控制；最新本地测试包单 EXE 17,648,640 字节、ZIP 19,846,558 字节，仍是混合迁移版本。
- 仍未完成：旧驻留账本的内容所有权核验、保存覆盖项/跨包附加项的事务安装、挂载与无人机根引用的完整整合、全部参数描述和界面切换。本轮规划、资源构建预览与导出接口不等于正式游戏补丁安装已接入。

- 原生参数绑定、预设差异预览及值应用：共享物理字段相同值去重，冲突拒绝整批应用；缺失项仅在显式选择后跳过。完整全局预设的“未列出字段恢复”和动态引用重建仍未完成。
- 护甲静态目录已迁移为 JSON 数据，原始数值另存固定指纹基准；32 个被动的 75 个命名数值通过独立二进制解析核对。原生 AVP1 捕获、校验、恢复已提供独立接口；正式界面尚未切换。
- 护甲被动数组解析与组合：保留当前编辑值、保留/移除自身被动、叠加/取最强、效果去重、最多三条描述、保留无关块及块间数据。已补充被动家族层面的“所有护甲”范围与独立配置覆盖规则，空独立配置仍优先于全局；清空后的空组不计入安装组数。“取最强”先按相同数值去重，再比较操作类型的强度，与旧引擎一致。
- 原生护甲会话已整合命名数值、组合选择、100 步联合撤销/重做及组合明文导出。INI 兼容中英文名称和当前文件的数字 ID，忽略配置中的数值覆盖行；选择通过 JSON 对象传输，密集或稀疏 ID 均不转成数组。新状态快照同时保存 AVP1 数值和组合配置，完整验证后才应用，失败不改变任一部分；INI 与明文导出只创建新文件，拒绝覆盖输入及过期磁盘快照。配置文件只在显式导出时写入，尚未自动接管旧版 `armory.ini`。
- 本轮补充验证：64 项 Rust 单元测试通过；39 组配置在隔离目录逐字节对照旧组合构建器，75 个命名数值、联合快照、清空计数、密集/稀疏选择、100 步历史、无变化/失败操作保留重做、外部修改和覆盖拦截均通过。原生 MCP 与标准输入接口共享这份护甲选择和撤销状态。对照脚本仅测试进程使用 LuaJIT，独立 Rust EXE 在无 Lua/DLL 的隔离目录运行。
- 护甲后续工作包括完整全局预设、旧配置自动保存和正式界面联动。Flutter 护甲页继续使用兼容核心，直到护甲组合、具体护甲分配与装备参数能够共享同一会话。
- 原生文件事务库已覆盖备份、准备回读、Unicode 文件替换、新增/删除、提交失败回滚与备份指纹恢复；仅在隔离目录测试，尚未接入正式游戏安装入口，也未实现进程中断后自动恢复。
- 原生诊断脱敏包含嵌套 JSON、其他电脑的用户路径、中文用户名与凭据；诊断收集与完整日志导出尚需接入。
- 可信原值表索引按类型与布局缓存；批量字段重叠检查使用有序索引，避免逐项全表比较。

- 新增独立的 `shodan-native` 可执行文件，不加载 Lua、Flutter、LuaJIT 或兼容宿主。
- Rust 原生 LDLD 索引：识别重复类型的数据块，保留块前的非零元数据，校验头部和载荷边界，拒绝无法解析的后缀。
- Rust 编辑文档：磁盘快照、可信原始数据和待应用修改分别保存。原始数据缺失时不提供虚假的恢复值。
- 数值修改限制在数据块载荷内，拒绝重叠修改与打开后发生变化的磁盘文件。此阶段仅在内存生成字节，不安装游戏文件。
- 测试覆盖浮点位解释、负重力、大数值、修改值不冒充原值、布局不匹配、错误输入与截断数据。
- 原生 NaCl 密封文件编解码采用 RustCrypto `crypto_box`；SHA-256 与游戏使用的 Murmur64 校验均不依赖 DLL。6 份本地原始数据完成与 libsodium 的双向互操作验证（测试进程加载参考库，Rust 程序不加载）。
- 哈希修正与密封导出已串联：有界并行搜索、取消、超时、保护区域检查和封装后回读。仅在显式指定已编辑浮点字段时才允许借用其低位，报告给出实际调整；不安装游戏文件。
- 原生 ID 行表与 64 位哈希表索引、按记录身份读取字段。6 份本地数据中 26 张受支持表、2660 个记录的 ID 和偏移与独立校验器一致；重排记录后原值仍可按 ID 对照。
- 补充载具、护盾、护卫犬依赖、投掷物、背包、制导、地雷及潜兵组件等布局后，本地回归扩展至 61 张表、7210 条记录。战略配备 ID 修正为行内 +4，配件 ID 使用 +8；测试独立断言这两项规则，不再仅跟随 Rust 输出猜偏移。
- 原生 `schema` 接口已提供伤害与射弹的基础中文参数描述，质量、重力为 f32，四个状态槽均含强度字段。这里只表示原始记录字段已描述，不代表完整装备引用链与选择规则已迁移。

## 仍需迁移

### 提交与合并条件

阶段性改动以草稿 PR 供审阅。正式切换需要完成全部非界面逻辑迁移，检查差异和完整回归，并确认必需 CI 通过及审查问题已解决。

| 验收领域 | 原生 Rust 状态 | 合并前必须补齐 |
| --- | --- | --- |
| 密封编解码、哈希、LDLD | 已有原生实现及独立对照 | 全版本数据回归 |
| 表索引、可信原值 | 部分表已覆盖 | 剩余布局与游戏版本绑定 |
| 单项/批量编辑与历史 | 已支持原子批量、100 步撤销/重做 | 完整字段类型、标志位及多文件事务 |
| 预设 | 文本容器已迁移 | 参数别名、引用变更、护甲配置语义与实际应用 |
| 中文名称、搜索、共享影响 | 尚未整体迁移 | 与旧版字段及名称清单逐项核对 |
| 引用链、资源诊断与驻留 | 原生读取、引用图、来源匹配和槽位规划已提供 | 完整语义依赖、补丁所有权、已有覆盖项保留、安装回滚接入 |
| 安装、备份和恢复 | 尚未接入原生正式入口 | 并发修改、故障回滚、权限错误、进度 |
| 更新、MCP、诊断与配置 | 原生更新任务、MCP 和脱敏已提供 | 正式界面接入、配置持久化、完整诊断收集及旧接口等价验证 |
| Flutter 界面适配 | 更新功能已接入 Rust；编辑业务仍使用兼容宿主 | 切换全部编辑调用后移除 Lua/DLL 依赖 |

当前原生编辑历史只保存内存参数状态，不假装可以撤回已经安装的资源补丁；新开文件创建新的历史。失败或无变化的操作不清空重做记录。

1. 原始基准来源认证、完整安装事务与备份集成。
2. 剩余表布局、动态数组、组件与引用链解析；目前仅迁移部分布局，不能视为全部游戏数据已覆盖。
3. 全部参数描述、共享影响、中文名称及搜索索引。
4. 护甲、装备与全局预设的导入导出和兼容规则。
5. 资源补丁、备份、事务写入、恢复、进度与诊断。
6. 现有界面接入原生 Rust 接口；界面只负责展示与交互，不承载数据读写和业务规则。

完成上述迁移并验证前，4.6.0 仍使用原有兼容数据层，不能称为纯 Rust 成品。新入口支持 `inspect`、`inspect-sealed`、`tables` 只读检查和 `seal-copy`、`unseal-copy`、`prepare-copy` 新文件导出，不覆盖现有文件，不连接正式安装按钮。密封认证和游戏哈希匹配均不能证明载荷为原版数值。

## 验证

原生资源接口测试：`tests/test_native_residency.py` 构造独立 DSAR/bundle 与 bank，核对高位资源身份、事件目录、缺失事件、扫描、旧记录复用；`tests/test_native_audio_real.py --root <游戏data目录>` 只读对照真实 bank。`tests/test_native_mcp.py` 检查鉴权、Origin、配置、共享编辑历史和关闭监听；`tests/test_native_update.py` 默认离线，核对中文说明、修订号、下载范围及后台失败恢复。

原生 Windows 网络调用参考：[WinHttpOpen](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpopen)、[WinHttpQueryHeaders](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpqueryheaders)。

原生预设容器编解码已实现 `SHODAN-PRESET 1`，保留装备哈希、参数标识、中文名称及护甲配置文本，拒绝重复字段、非有限数值和装备范围混入。`preset-inspect` 返回校验结果和规范化文本。护甲数值及家族组合分别有原生校验和联合状态接口，但还没有与装备全局预设、具体护甲分配组成统一事务；`slot1_strength` 等旧参数的别名解析、动态引用更新和实际应用仍需要完整原生参数描述，不能视为全部预设迁移完成。

护甲会话接口：`armor-open` 从当前明文及指纹匹配的原值创建会话；`armor-profiles-load/get/update/remove/clear` 管理组合；`armor-state-capture/apply` 联合保存恢复；`armor-history/undo/redo` 管理内存编辑历史；`armor-compose-preview/export-copy` 先渲染数值再组合。`armor-profiles-export-copy` 输出兼容 INI，`armor-export-copy` 保留仅数值导出。预览分别报告活动配置组数和实际展开应用组数，明确 `installed=false`，不将复制导出当作游戏安装。

`apply-batch` 对已经索引的字段批量应用：先解析全部记录，写入异常时恢复此前的待应用状态；拒绝重复或重叠字段。35 项 Rust 测试和独立进程回归覆盖末项失败回滚、已有修改保留、完整 64 位哈希与中文预设往返。

`shodan-native --stdio` 提供逐行 JSON 原生会话接口，包含 `info/open/index/get/set/restore/preview/export-copy/close`。请求使用 `id/method/params`，响应保留 ID 并返回 `ok/result` 或 `ok/error`。记录身份使用 `id:9` 或 `hash:完整十六进制哈希`，避免 JavaScript 浮点数截断 64 位哈希。`open` 失败不丢弃现有会话；导出只创建新明文文件，先核对当前磁盘快照，不覆盖已有文件，不代表已安装游戏。Flutter 更新检查已使用原生接口，编辑业务尚未整体切换。

独立进程测试：`python tests/test_native_api.py`。仅写入项目隔离临时目录；覆盖精确字节比较、原文件保持不变、拒绝覆盖、外部修改拦截、错误恢复和正常退出。该环境的用户系统临时目录对原生进程写入受限，测试目录因此明确放在项目 `dist` 下。

新增原生 `Session`：整合只读磁盘快照、一次性表索引、按 ID 编辑、可信原值查询和恢复、待应用修改及过期快照拦截。未找到可信原值时禁止恢复；重复 ID 表拒绝编辑。尚未接入正式界面，不能视为兼容数据层已移除。

新增原生 `baseline` 模块：仅接受清单中六份原值文件的固定 SHA-256 指纹；按数据块类型和记录 ID/哈希读取原值，不使用当前文件的行位置推断默认值。记录重排、新增记录、重复 ID 和越界字段均有独立检查。指纹验证不代替游戏版本核对；此模块尚未接入正式界面的恢复按钮。

```sh
cargo test --workspace
cargo build --release --bin shodan-native
target/release/shodan-native inspect offline/originals/generated_arc_settings.dl_plain
python tests/test_native_data.py --exe target/release/shodan-native.exe --originals offline/originals --output dist/native-data-audit.json
python tests/test_native_codec.py --exe target/release/shodan-native.exe --originals offline/originals --output dist/native-codec-interop
python tests/test_native_correction.py --exe target/release/shodan-native.exe --originals offline/originals --output dist/native-export-regression
python tests/test_native_tables.py --exe target/release/shodan-native.exe --originals offline/originals --output dist/native-tables-audit.json
```

数据对照在本地原始文件上进行，报告只包含文件名、大小和块数量，不包含用户目录。自动测试不写入游戏。

格式与接口依据：[RustCrypto crypto_box](https://docs.rs/crypto_box/0.9.1/crypto_box/)、[libsodium sealed boxes](https://doc.libsodium.org/public-key_cryptography/sealed_boxes)。
